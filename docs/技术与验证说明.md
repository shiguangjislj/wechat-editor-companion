# 技术与验证说明

本文件记录v0.7.10的实现方式和验证边界。面向使用者的安装和操作步骤见[项目首页](../README.md)。

## 视频队列

视频文件按4MiB分片保存在扩展的IndexedDB中，可跨公众号页面和扩展后台重启读取。扩展不设上传服务器，也不调用微信私有接口。暂存仍受本机磁盘空间限制；卸载扩展、清除扩展站点数据或开始新批次会清理旧暂存。

在图文编辑页进入视频功能时，扩展尝试依次点击原生“视频→素材库→本地上传”，并在独立上传页恢复面板及队列。每条视频仍通过公众号原生上传控件上传。标题默认是去除扩展名的文件名，封面默认选择微信生成的第1张推荐图。原创声明由使用者在原生页面决定。首次遇到视频上传协议时由使用者阅读并勾选；后续只有协议文字和链接完全相同时，扩展才会自动勾选。每条视频仍由使用者点击微信原生“保存”。

保存动作会唤醒素材库核验。扩展读取“素材库→视频”列表中单条素材的实际标题、审核状态和更新时间，匹配后标为“已上传”；未能匹配时保留“待核对”，不会仅凭保存按钮点击宣称入库成功，也不会阻止处理下一条。核验在保存后短时进行，页面加载或列表变化会再次唤醒，避免长期轮询。用户可手动确认或重新上传，重新上传前应检查素材库以免重复。素材入库后，文章中的插入位置由使用者选择。

## 图文样式

文字排版只处理不含图片或视频的段落，保留原文字、链接和强调结构；通过编辑器原生命令替换段落富文本并设置对齐。图片处理保留原图地址和媒体属性，通过原生编辑事务更换所选图片的显示外框。逐张提交后等待编辑区稳定，再处理下一张；文章文字、链接、嵌入内容或所选图片身份变化时停止，防止错改。整批完成后被动复核。

撤销图片样式会基于当前文章，只替换最近一批所选图片的样式，并等待编辑器重绘后逐张核对。撤销记录只存在于当前页面：刷新页面或更新扩展后不会保留。编辑区显示成功也不代表公众号已保存，需使用微信原生保存，再重新打开文章和手机预览检查。

## 验证结果与边界

截至2026年10月28日，`npm test`的45项本地测试通过。真实Chrome的本地`contenteditable`验证页中，21张图片可批量应用并一次撤销，文章文字保持不变、样式外框全部移除。视频跨页面队列、文件暂存、原生控件选择和素材列表匹配由本地模拟页与测试覆盖。真实公众号账号中的视频批量入库、大文件容量，以及微信原生保存后样式和手机端效果，仍需继续验收；本地测试不能替代这些结果。

开发者可运行`npm ci`和`npm test`。`src/content.js`负责面板与文件选择，`src/editor-adapter.js`负责编辑器样式事务，`src/video-batch-storage.js`负责视频分片，`src/video-batch-background.js`负责队列状态，`src/video-batch-worker.js`负责公众号原生页面操作。`test/`中的页面是本地测试夹具，并非真实公众号。
